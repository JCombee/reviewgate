# 3.1: Merge suggestions into `CommentsPanel.tsx`'s grouped list

**Story ID:** 3.1
**Epic:** 3 — Suggestions-in-Comments
**Slug:** merge-suggestion-rows
**Status:** done

## Story

As a **reviewer**,
I want **suggestions from the automatic pass grouped into the same file/section list as my comments**,
so that **I have one place to see everything waiting for my attention, instead of checking the diff separately for suggestions**.

## Acceptance Criteria

1. `CommentsPanel.tsx` accepts `review.suggestions` (already passed in via `review`) and merges them with `review.comments` into one list of rows before grouping, without changing the `Comment`/`Suggestion` types.
2. The merged rows are grouped exactly as comments are today: general (`scope: "global"`) first, then commit message (`scope: "commit_message"`), then per-file in diff order (`summary.files` order), matching `groupComments`'s existing grouping rules.
3. Within a file group, comment rows and suggestion rows sharing that file are ordered by line number together (a suggestion on line 10 appears before a comment on line 20 in the same file group), reusing the existing `byLine` comparator logic extended to the merged row type.
4. `review.comments`-only behavior (grouping, counts, ordering) is unchanged for a review with zero suggestions — this story must not regress the existing comment-only rendering.
5. This story does not yet render suggestion-specific visuals (badge/border/severity/actions) — a suggestion row may render minimally (e.g. via a placeholder) for now; that visual/interactive polish is Story 3.2.

## Tasks / Subtasks

- [ ] Define a `ReviewRow` union type (`{ kind: "comment"; comment: Comment } | { kind: "suggestion"; suggestion: Suggestion }`) local to `CommentsPanel.tsx` (AC: #1)
- [ ] Rename/refactor `groupComments(comments, summary, filter)` to accept `ReviewRow[]` — extract each row's `scope`/`path`/`startLine`/`status`-equivalent via small accessor helpers so the grouping logic doesn't need `if (row.kind === ...)` branches everywhere (AC: #1, #2)
- [ ] Build the merged `ReviewRow[]` from `review.comments` and `review.suggestions` before calling the grouping function (AC: #1)
- [ ] Extend `byLine` (or an equivalent comparator) to sort mixed rows by line number within a group (AC: #3)
- [ ] Add/extend unit tests asserting comment-only review output is byte-identical to today's grouping (AC: #4)
- [ ] Render suggestion rows with a minimal placeholder (e.g. reusing `CommentRow`'s shell with a "(suggestion)" label) so the merge is visibly complete pending Story 3.2 (AC: #5)

## Dev Notes

- Today's grouping lives entirely in `groupComments` (`packages/web/src/components/CommentsPanel.tsx:179-224`): it filters by `Filter` status, splits into `global`/`commit_message`/per-path buckets using `summary.files`' `index` for file ordering, and sorts each file's comments with `byLine` (`startLine` then `createdAt`). [Source: packages/web/src/components/CommentsPanel.tsx]
- `Comment` and `Suggestion` already share nearly identical positional fields: both have `scope: CommentScope`, `path?`, `side?`, `startLine?`, `endLine?`, `anchorSnippet?`, `round`, `body`, `createdAt` — only `status`/`kind`/`author` differ (comment) vs. `severity`/`status: SuggestionStatus`/`dismissedReason`/`duplicateOf`/`promotedToCommentId` (suggestion). This shared shape is exactly why grouping-by-position can be extracted into small accessor helpers rather than duplicating the grouping function. [Source: packages/core/src/review/types.ts]
- `CommentsPanel` already receives the full `review: Review` object as a prop (`packages/web/src/components/CommentsPanel.tsx:24-35`), so `review.suggestions` requires no new prop — only a change to what the component does with data it already has. [Source: packages/web/src/components/CommentsPanel.tsx]
- Do not merge the underlying `Comment`/`Suggestion` types or persist a combined type to disk — the merge is presentation-only, inside `CommentsPanel.tsx`, per the tech-spec's explicit decision to keep the types separate so suggestions can never silently affect the approval gate. [Source: tech-spec.md#decisions-log-summary]
- `groups` (the `Group` interface, `CommentsPanel.tsx:166-173`) currently types `comments: Comment[]` — this becomes `rows: ReviewRow[]` (or similarly renamed) as part of this story's refactor. [Source: packages/web/src/components/CommentsPanel.tsx]

## Testing

- **Approach:** unit tests for the grouping/sorting logic, extracted so it is testable independent of React rendering (matching the existing `groupComments` function's pure-function shape, which is already unit-testable without mounting the component).
- **Key scenarios:** a review with only comments groups identically to today (regression); a review with only suggestions groups them by file the same way comments would; a review with both on the same file interleaves them by line number; a review with no comments and no suggestions renders the existing empty state.
- **Per-AC verification:** AC #1/#2 → grouping unit test asserts general/commit-message/per-file order matches today's comment-only behavior when suggestions are absent, and correctly buckets suggestions when present; AC #3 → a mixed-file test asserts line-ordered interleaving; AC #4 → a snapshot/equality test comparing this story's output against a captured pre-change fixture for a comments-only review; AC #5 → visual confirmation only (formal visual testing is Story 3.2's scope).
- **Fixtures / mocks:** small hand-built `Review` fixtures with 2-3 comments and 2-3 suggestions across 2 files, including at least one file with both kinds present.
- **Edge cases to cover:** a suggestion with no `path` (global scope); a suggestion and a comment on the exact same line (stable ordering, e.g. tie-break by `createdAt` as `byLine` already does for comments).

## Dev Agent Record

Implemented entirely inside `packages/web/src/components/CommentsPanel.tsx` (no other files touched).

- Added the `ReviewRow` union type (`{ kind: "comment"; comment } | { kind: "suggestion"; suggestion }`) and small accessor helpers (`rowId`, `rowScope`, `rowPath`, `rowStartLine`, `rowCreatedAt`) so the grouping logic branches on row shape only in those helpers, not throughout `groupRows`.
- Renamed `groupComments` → `groupRows` (per the Tasks list's "rename/refactor" instruction) and changed its signature to `(rows: readonly ReviewRow[], summary, filter) => Group[]`. `Group.comments: Comment[]` was renamed to `Group.rows: ReviewRow[]` as anticipated in the Dev Notes.

- `counts` (the four filter-tab totals) is untouched — still comment-only, per AC #4 and this story's scope (Story 3.3 owns any change there).
- **Judgment call — interim filter behavior for suggestion rows in this story:** since suggestion→Filter status mapping is explicitly Story 3.3's job, `groupRows`'s filter predicate keeps suggestion rows only under the "All" tab for now (comment rows are filtered exactly as before under every tab). This means a suggestion will not appear under the default "Open" tab until Story 3.3 lands its mapping — documented in a code comment at the predicate (`groupRows`, the `row.kind === "suggestion"` branch). This does not regress any comment-only behavior (AC #4) and satisfies AC #5 (no visual/interactive polish yet).
- Suggestion rows render via a new minimal `SuggestionRowPlaceholder` (badge-free: "(suggestion)" label + line + body), replaced by Story 3.2 with real `SuggestionCard`-derived rendering.
- Tests: added `packages/web/src/components/CommentsPanel.test.ts` (plain `.test.ts`, matches the vitest `include` glob `packages/*/src/**/*.test.ts`) exercising `groupRows`/`byLine` directly — regression test for comment-only grouping/filtering (byte-for-byte same grouping/ordering as before), suggestion-only grouping by file, mixed-file line interleaving, same-line tie-break, no-path/global suggestion, and the empty-state case. All new tests are pure-function tests against the exported `groupRows`/`byLine`/`ReviewRow`, no component mounting needed.
