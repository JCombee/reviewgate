# 3.2: Suggestion row rendering + actions reused from `SuggestionCard.tsx`

**Story ID:** 3.2
**Epic:** 3 — Suggestions-in-Comments
**Slug:** suggestion-row-rendering
**Status:** done

## Story

As a **reviewer**,
I want **a suggestion in the comments list to look unmistakably different from a real comment, and to support the same accept/dismiss/discuss actions it already has**,
so that **I never confuse a non-binding suggestion with a comment I or the assistant actually wrote, and I don't lose functionality by seeing it in the list**.

## Acceptance Criteria

1. Suggestion rows in `CommentsPanel.tsx` (the placeholder from Story 3.1) are replaced with real rendering carrying the same visual markers as `SuggestionCard.tsx`: a "Suggestion" badge, a dashed border, and the severity color (`SEVERITY_COLOR`/`SEVERITY_LABEL`) matching `suggestion.severity`.
2. A suggestion row exposes the same actions available in `SuggestionCard.tsx` for its current status: `pending` → Accept / Dismiss / Discuss; `dismissed` → Reopen; `accepted` → a static "Accepted as a comment." label — with identical `api` calls (`acceptSuggestion`, `dismissSuggestion`, `reopenSuggestion`).
3. The "Accept" action, when used from the comments list, opens the same inline `CommentForm` editing flow `SuggestionCard.tsx` already uses (pre-filled with `suggestion.body`), not a stripped-down alternative.
4. A dismissed suggestion in the list is visibly muted (matching `SuggestionCard`'s `opacity-60` treatment when `dismissed`), consistent with how a resolved/outdated comment row is already muted (`CommentRow`'s `opacity-70` when `status !== "open"`).
5. Comment rows are visually unchanged from before this story (no shared restyling that bleeds into `CommentRow`'s existing look).

## Tasks / Subtasks

- [ ] Extract or reuse the badge/border/severity styling from `SuggestionCard.tsx` (either by rendering a trimmed variant of `SuggestionCard` inside the list, or a small shared sub-component both `SuggestionCard.tsx` and `CommentsPanel.tsx` import) (AC: #1)
- [ ] Wire Accept/Dismiss/Discuss/Reopen actions for suggestion rows using the same `api` calls `SuggestionCard.tsx` already makes (AC: #2)
- [ ] Reuse `CommentForm` (already imported by `SuggestionCard.tsx`) for the in-list Accept flow (AC: #3)
- [ ] Apply the dismissed-opacity treatment to suggestion rows (AC: #4)
- [ ] Manually verify `CommentRow`'s rendering is pixel-identical to before this story (AC: #5)
- [ ] Wire the "Discuss" action's `onDiscuss` callback through to whatever the panel already receives for this purpose (see `Overview.tsx`'s existing `onDiscuss` wiring into `App.tsx`'s `chatDraft`) so "Discuss" from the comments list behaves the same as "Discuss" from the diff view

## Dev Notes

- `SuggestionCard.tsx`'s existing visual contract (its own doc comment): "Deliberately different from a comment: a dashed border, a 'Suggestion' badge, muted colour. As long as you do nothing it stays a suggestion and nothing about the review changes — it does not count towards the button and it does not go to Claude." This story's job is to carry that same contract into the comments list, not to invent a new visual language for suggestions. [Source: packages/web/src/components/SuggestionCard.tsx]
- Exact styling reference: badge `<span className="rounded border border-[var(--rg-border)] px-1">Suggestion</span>`; card wrapper `border border-dashed border-[var(--rg-border-strong)]`; severity color via `SEVERITY_COLOR: Record<Severity, string>` (`blocker` → `var(--rg-status-deleted)`, `consideration` → `var(--rg-status-modified)`, `nit` → `var(--rg-text-faint)`); dismissed state adds `opacity-60`. [Source: packages/web/src/components/SuggestionCard.tsx]
- `SuggestionCard`'s action set is fully status-driven: `pending` shows Accept/Dismiss/Discuss; `dismissed` shows Reopen; `accepted` shows a static label; an `auto` (dismissedReason === "auto_duplicate") note renders above the actions. Reuse this exact branching rather than reinventing it — importing and rendering `SuggestionCard` itself (rather than re-implementing its internals) is the lowest-risk approach, provided its outer layout (currently a `my-1 rounded ...` block) fits inside `CommentsPanel`'s `<li>` row structure without visual conflicts. [Source: packages/web/src/components/SuggestionCard.tsx]
- `CommentRow`'s muting today is `opacity-70` when `comment.status !== "open"` (`CommentsPanel.tsx:113`) — suggestion rows should use `SuggestionCard`'s own `opacity-60` for dismissed, since the two are already slightly different values in the existing codebase; do not force them to match, just keep each consistent with its own existing precedent. [Source: packages/web/src/components/CommentsPanel.tsx, packages/web/src/components/SuggestionCard.tsx]
- `CommentForm` (imported by `SuggestionCard.tsx` from `./CommentForm.jsx`) is the existing accept-flow input — confirm `CommentsPanel.tsx` can import it the same way (no prop mismatch) since `CommentsPanel.tsx` does not currently import it. [Source: packages/web/src/components/SuggestionCard.tsx]
