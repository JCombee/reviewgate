# 1.2: One `ReviewAgent` per chat id in `Session`

**Story ID:** 1.2
**Epic:** 1 — Multiple Chats
**Slug:** server-chat-map
**Status:** done

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **reviewer using the chat panel**,
I want **each chat thread to run its own, independent assistant conversation on the server**,
so that **asking a question in one chat never leaks context into, or gets confused with, another chat in the same review**.

## Acceptance Criteria

1. `Session` (`packages/server/src/session.ts`) holds a `Map<string, ReviewAgent>` keyed by chat id instead of the single `#agent: ReviewAgent | null` field.
2. `Session.chat(chatId: string, message: string): Promise<Review>` replaces the current `chat(message: string)`: it appends the user message to the `Chat` in `review.chats` matching `chatId`, lazily creates that chat's `ReviewAgent` on first use, streams the answer via the existing `chat-token` SSE event, and appends the assistant's reply to that same `Chat`'s `messages`.
3. `Session.createChat(title?: string, model?: string | null): Promise<Review>` appends a new, empty `Chat` (no messages, the given or default title, the given or `null` model) to `review.chats` and persists it.
4. Calling `chat(chatId, message)` for an unknown `chatId` throws a clear error rather than silently creating a chat or crashing.
5. The automatic suggestion pass (`runReviewPass`) is unaffected — it continues to use its own one-off agent call and does not read or write `review.chats`.

## Tasks / Subtasks

- [ ] Replace `#agent: ReviewAgent | null` with `#agents = new Map<string, ReviewAgent>()` (AC: #1)
- [ ] Add a private `#agentFor(chatId: string): ReviewAgent` that looks up the chat in `review.chats`, throws if missing, and lazily constructs + caches a `ReviewAgent` (passing that chat's `model`) on first call (AC: #1, #4)
- [ ] Rewrite `chat(message: string)` as `chat(chatId: string, message: string)`, using `#agentFor(chatId)` and appending to the matching `Chat.messages` in both the "with question" and "with answer" `commit()` calls (AC: #2)
- [ ] Add `createChat(title?, model?)` that appends a new `Chat` via `randomUUID()` for its id and `commit()`s the result (AC: #3)
- [ ] Confirm `runReviewPass` continues to construct/use its own `ReviewAgent` path unchanged (it currently does not go through `#agent`/chat at all — verify no accidental coupling was introduced) (AC: #5)
- [ ] Add `packages/server/src/session.test.ts` covering AC #2-#4

## Dev Notes

- Today `Session` has exactly one `#agent: ReviewAgent | null`, constructed once in the static `Session.start`/resume path (`session.ts:118-123`) with `repoRoot`, `patch`, `transcriptPath`, `projectDocs` — no `model`. `chat(message)` (`session.ts:219-248`) always uses `this.#agentOrThrow()`, appends to `this.#review.chat`, and calls `agent.ask(prompt, onToken)`; the first message of the (single) chat carries the full `contextPrompt()`, later messages resume the SDK session via `ReviewAgent`'s internal `#sessionId`. [Source: packages/server/src/session.ts]
- Preserve the "first message carries context, later messages resume" behavior *per chat*: the condition `this.#review.chat.length <= 1` (session.ts:235) must become "is this the first message in *this* chat's `messages` array", evaluated per `Chat`, not per review. [Inference]
- `ReviewAgent#sessionId` (an SDK `resume` id) already lives inside each `ReviewAgent` instance (`packages/server/src/agent.ts`, `#sessionId: string | null`) — giving each chat its own `ReviewAgent` instance automatically gives it its own independent SDK session with no extra bookkeeping needed in `Session`. [Source: packages/server/src/agent.ts]
- `commit(next: Review)` (session.ts:135-139) is the existing single choke point that both saves to `ReviewStore` and emits the `review` SSE event to every listener — reuse it unchanged; do not add a parallel persistence path for chats. [Source: packages/server/src/session.ts]
- `AgentContext`'s `model` field (added by Story 2.1, not this story) is what `#agentFor` will eventually pass through when constructing a `ReviewAgent` — until Story 2.1 lands, construct with `model: null`/omitted so this story is not blocked on Epic 2. [Source: tech-spec.md#key-components]
- This story does not touch `app.ts` routes or `reviewClient.ts` — those are Story 1.3. Route handlers still calling `s.chat(message)` (one argument) will fail to compile until 1.3 updates them; that is expected and acceptable within this story's scope, but flag it explicitly in the PR/commit so 1.3 is understood as the very next required story. [Inference]

## Testing

- **Approach:** unit tests in a new `packages/server/src/session.test.ts` (no such file exists today; `agent.test.ts`, `app.test.ts`, `claude-path.test.ts` are the existing sibling patterns to follow for mocking/setup style).
- **Key scenarios:** two chats created via `createChat`, messages sent to each, assert each `Chat.messages` only contains its own conversation; sending to an unknown `chatId` throws; the first message in a new chat includes the full context prompt while a second message in the same chat does not (mirroring today's single-chat behavior, verified per-chat).
- **Per-AC verification:** AC #1 → type-level check (no more `#agent` field) plus a test asserting two chats get two distinct agent instances (e.g. via distinguishable mock `ask` call context); AC #2 → integration-style test sending two messages in the same chat and asserting both land in that chat's `messages` in order; AC #3 → test asserting `createChat` adds exactly one empty `Chat` and returns it in the updated `Review`; AC #4 → test asserting `chat("nonexistent", "hi")` rejects; AC #5 → existing `runReviewPass` tests (if any, or to be added) remain green with no `review.chats` interaction.
- **Fixtures / mocks:** mock/stub `ReviewAgent.ask` (as `agent.test.ts` likely already does for SDK calls) to avoid real Claude Agent SDK calls in unit tests.
- **Edge cases to cover:** sending a message to a chat with zero prior messages vs. one prior message (context-prompt boundary); creating a chat with no title/model (defaults); calling `chat` before any chat exists in a freshly created review.

## Learnings from Previous Stories

- From 1.1: the `Chat` type shape is `{ id, title, model: string | null, messages: ChatMessage[], createdAt }`; `review.chats` replaces `review.chat` and `ReviewStore.load` already migrates legacy single-chat reviews, so `Session` can assume `review.chats` is always present and well-formed by the time it runs.

## Dev Agent Record

Implemented as specified:

- Replaced `#agent: ReviewAgent | null` with `#agents = new Map<string, ReviewAgent>()` on `Session`. Also added `#patch: string`, `#transcriptPath: string | null`, `#projectDocs: string` private fields (populated from the three constructor args `Session.create` used to build the single shared `ReviewAgent`'s context) plus a private `#agentContext(): AgentContext` helper, since that context is now needed in three places (`#agentFor`, `runReviewPass`) instead of once.
- Added `#agentFor(chatId): ReviewAgent`: looks up the chat in `review.chats`, throws `ReviewError(\`unknown chat: ${chatId}\`, 404)` if missing, otherwise lazily constructs and caches a `ReviewAgent` in `#agents` keyed by `chatId`.
- Rewrote `chat(message)` → `chat(chatId, message)`: the empty-message check runs first (unchanged ordering), then `#agentFor(chatId)` is called before anything is appended, so an unknown `chatId` throws before any mutation (AC #4). Added a private `#withMessage(chatId, role, body): Review` helper used for both the "with question" and "with answer" `commit()` calls, replacing the old flat `review.chat` array splices with a `chats.map()` that only touches the matching chat. The "first message carries context" check now reads `thisChat.messages.length <= 1` on the specific chat instead of the old review-wide `review.chat.length <= 1`.
- Added `createChat(title?, model?): Promise<Review>`: appends a new `Chat` (`randomUUID()` id, trimmed title or `"Chat"` default, `model ?? null`, empty `messages`, `createdAt` now) via the existing `commit()` choke point.
- `runReviewPass` no longer reads the old `#agent` field (removed, along with the now-dead `if (!this.#agent)` guard — `ReviewAgent`'s constructor never throws, so that check was defensive-only and unreachable; real "assistant unavailable" errors already surface through the existing `try/catch` around `agent.reviewPass`/`agent.ask`). It now constructs one fresh, uncached `ReviewAgent` per call via `#agentContext()` — the "one-off agent call" the AC asks for — and continues to touch only `review.suggestions`/`review.rounds` through `addSuggestions`, never `review.chats` (AC #5, covered by a new test).
- Removed the now-unused `AgentUnavailable` import from `session.ts` (its only use, `#agentOrThrow`, is gone).
- Added `packages/server/src/session.test.ts` (new, 11 tests) covering: `createChat` defaults/overrides/whitespace-title fallback and persistence via `store.load`; `chat` rejecting an unknown `chatId` without any side effect; question-then-answer ordering in one chat; independence of two chats' message histories; two chats getting two distinct `ReviewAgent` instances (asserted via the `this` receiver seen by a mocked `ReviewAgent.prototype.ask`) vs. one chat reusing the same instance across two messages; the context-prompt-only-on-first-message behavior verified per chat; empty-message rejection; and `runReviewPass` leaving `review.chats` untouched. All `ReviewAgent.ask` calls are stubbed via `vi.spyOn(ReviewAgent.prototype, "ask")` (no existing mocking convention for the SDK-backed class existed yet, since `agent.test.ts` only exercises its pure helper functions — this establishes the pattern the Dev Notes anticipated).

Judgment calls:
- **Chosen error type for AC #4:** the story doesn't specify what `chat()` should throw for an unknown `chatId`, only that it must be "a clear error." Used `ReviewError` (from `@reviewgate/core`, already the codebase's convention for HTTP-status-bearing domain errors — see `mutations.ts`) with status 404, rather than a plain `Error`. This lets Story 1.3's route handler map it to a 404 response the same way `app.ts` already does for other `ReviewError`s, without inventing a second error-to-status convention.
- **Context storage:** rather than re-deriving `patch`/`transcriptPath`/`projectDocs` on every `ReviewAgent` construction, they're captured once in `Session.create()` (exactly as before) and stored as new private fields, reused by every chat's agent and by the pass's one-off agent. This preserves the exact previous behavior (one `readProjectDocs` read per session, not per chat/pass) and was the natural reading of Dev Notes' "same context, no extra bookkeeping needed."
- **`AgentContext.model`:** left untouched (no `model` field passed to `ReviewAgent` yet) per the Dev Notes' explicit instruction to defer that to Story 2.1; `#agentFor` ignores the chat's own `model` field for now.
- **Build state at handoff:** as flagged in this story's own Dev Notes, `packages/server/src/app.ts`'s `/api/review/:id/chat` route still calls `s.chat(message)` with one argument, so whole-repo `tsc -b` (and therefore `npm test`'s `pretest`) fails on that single call site until Story 1.3 updates the route. Verified in isolation instead: `npx tsc -b packages/core packages/server` shows exactly one remaining error (`app.ts:246`, the expected one-argument call site) and no errors in `session.ts` itself; `npx vitest run packages/core packages/server` (bypassing the `pretest` build gate) passes all 15 test files / 213 tests, including the untouched `app.test.ts` (which never exercises the chat route, so the stale one-argument call is harmless at runtime). Full `npm test` was confirmed green after Story 1.3 fixed the route.
