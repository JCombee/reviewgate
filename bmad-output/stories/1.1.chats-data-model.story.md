# 1.1: Replace `review.chat` with `review.chats` + legacy migration

**Story ID:** 1.1
**Epic:** 1 — Multiple Chats
**Slug:** chats-data-model
**Status:** done

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **ReviewGate maintainer**,
I want **the `Review` domain type to hold a list of named chat threads instead of one flat chat array**,
so that **later stories can let a reviewer open more than one independent conversation per review, without losing any existing chat history already on disk**.

## Acceptance Criteria

1. `packages/core/src/review/types.ts` defines a new `Chat` interface (`id`, `title`, `model: string | null`, `messages: ChatMessage[]`, `createdAt`) and `Review.chat: ChatMessage[]` is replaced with `Review.chats: Chat[]`.
2. `packages/core/src/api.ts` re-exports `Chat` alongside the existing `ChatMessage` export so `server` and `web` can import it from `@reviewgate/core/api`.
3. `ReviewStore.findOrCreate`'s new-review path (`packages/core/src/review/store.ts`) initializes `chats: []` instead of `chat: []`.
4. `ReviewStore.load` transparently migrates a review JSON file that still has the legacy `chat: ChatMessage[]` shape into `chats: [{ id, title: "Chat", model: null, messages: <old chat array>, createdAt: <review.createdAt> }]` (or `chats: []` if the legacy array was empty) before returning the `Review` to any caller. The on-disk file is not required to be rewritten by this story — migrating on read is sufficient.
5. All existing core fixtures/tests that construct a `Review` with `chat: []` (`mutations.test.ts`, `suggestions.test.ts`) are updated to `chats: []` and pass.

## Dev Notes

- Current shape: `Review.chat: ChatMessage[]` and `ChatMessage { id, role, body, at }` at `packages/core/src/review/types.ts:66-71,100`. [Source: tech-spec.md#data-model]
- `ReviewStore` is the only read/write path for review JSON: `load()` does `JSON.parse(raw) as Review` with no validation today, and `findOrCreate` constructs a brand-new review literal (including `chat: []`) when no candidate exists. [Source: packages/core/src/review/store.ts]
- Migration must happen in `load()`, not in `findOrCreate()`'s new-review branch alone — `findOrCreate()`'s `candidates` come from `list()`, which itself calls `load()`, so putting the migration in `load()` covers every read path in one place. [Inference]
- Do not rewrite the file to the new shape as a side effect of `load()` in this story — the next `store.save()` call (which happens on every mutation, per `store.ts`'s doc comment "the server writes on every mutation") will naturally persist the migrated shape. Forcing a write during a read adds risk (partial write mid-read) for no required benefit. [Inference]
- `packages/core/src/api.ts` re-exports the review types consumed outside `core` (`ChatMessage`, `Comment`, `Review`, etc. at lines 130-144) — `Chat` must be added to that list or `server`/`web` cannot import it via `@reviewgate/core/api`. [Source: packages/core/src/api.ts]
- This story only changes the data model and the store; it does not touch `session.ts`, `app.ts`, or any UI file — those are Stories 1.2-1.4. [Source: tech-spec.md#story-list]

## Testing

- **Approach:** unit tests only, in `packages/core/src/review/*.test.ts` (vitest, matching existing test file conventions in this directory).
- **Key scenarios:** new-review creation yields `chats: []`; loading a legacy `chat: [...]` file yields one migrated `Chat` with the old messages intact and `model: null`; loading an already-migrated file is a no-op; loading a file with neither field defaults to `chats: []` without throwing.
- **Per-AC verification:** AC #1 → `tsc`/typecheck catches any remaining `.chat` usage in `core`; AC #2 → an import of `Chat` from `@reviewgate/core/api` type-checks; AC #3 → new `store.test.ts` case asserts `findOrCreate` on an empty store returns `chats: []`; AC #4 → new `store.test.ts` case writes a legacy-shaped JSON file and asserts `load()`'s migrated output; AC #5 → existing `mutations.test.ts`/`suggestions.test.ts` suites pass unmodified in behavior, only the fixture literal changes.
- **Fixtures / mocks:** a hand-written legacy-shaped JSON string (`{"chat": [{"id": "...", "role": "user", "body": "...", "at": "..."}], ...}`) written directly via `fs.writeFile` to the path `ReviewStore.fileFor(id)` returns, bypassing `save()` (which would already write the new shape).
- **Edge cases to cover:** empty legacy `chat: []`; a review JSON with `chats` already present (must not double-wrap); a review JSON with neither `chat` nor `chats`.

## Dev Agent Record

Implemented as specified:

- Added `Chat` interface (`id`, `title`, `model: string | null`, `messages: ChatMessage[]`, `createdAt`) to `packages/core/src/review/types.ts` and replaced `Review.chat: ChatMessage[]` with `Review.chats: Chat[]`.
- Re-exported `Chat` from `packages/core/src/api.ts` alongside `ChatMessage`.
- `ReviewStore.findOrCreate`'s new-review literal now initializes `chats: []`.
- Added an exported `migrateLegacyChat(raw: unknown): Review` helper in `store.ts`, called from `load()` before returning. It is idempotent (`Array.isArray(review.chats)` short-circuits), defaults to `chats: []` when neither `chat` nor `chats` is present, wraps a non-empty legacy `chat` array into one `Chat` named `"Chat"` with `model: null` and `createdAt` taken from the review's own `createdAt`, and strips the old `chat` key from the returned object. Per the Dev Notes, the on-disk file is left as-is; migration happens only on read, and the next `save()` naturally persists the new shape.
- Updated `chat: []` fixtures to `chats: []` in `mutations.test.ts` and `suggestions.test.ts` as named in Tasks/Subtasks.
- Added `store.test.ts` cases: `findOrCreate` on an empty store yields `chats: []`; a legacy-shaped JSON file (written directly via `fs.writeFile` to `store.fileFor(id)`, bypassing `save()`) migrates to one `Chat` with the old messages, `model: null`, and the review's `createdAt`; an empty legacy `chat: []` migrates to `chats: []`; an already-migrated `chats` array passes through unchanged; a file with neither key defaults to `chats: []`.
