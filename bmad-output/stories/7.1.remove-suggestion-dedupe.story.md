# 7.1: Remove suggestion "remembering" (cross-round duplicate suppression)

**Story ID:** 7.1
**Epic:** 7 — Suggestion Dedupe Removal
**Slug:** remove-suggestion-dedupe
**Status:** review

## Story

As a **reviewer**,
I want **the automatic suggestion pass to stop suppressing a finding just because it resembles something I dismissed in an earlier round**,
so that **a real, recurring issue is not silently hidden from me again in a later round**.

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. `addSuggestions` no longer performs any duplicate-matching step: given a review with an earlier suggestion dismissed by the user and a new incoming finding whose body is highly similar to it, the new finding is added as a `pending` suggestion (not auto-dismissed) and is subject only to the severity cap; `AddSuggestionsResult` no longer has a `duplicates` field.
2. `findDuplicate`, `similarity`, `normalize`, `words`, `rangesOverlap`, `DedupeConfig`, `DEFAULT_DEDUPE`, and `DuplicateMatch` no longer exist in `packages/core/src/review/suggestions.ts` or in the `packages/core/src/index.ts` export barrel.
3. The `dedupe` field is removed from `ReviewGateConfig`, `DEFAULT_CONFIG`, and `mergeConfig` in `packages/core/src/config.ts`; a `.reviewgate.json` file containing a `dedupe` key still loads without error and the resulting config object carries no `dedupe` property.
4. `packages/web/src/components/SuggestionCard.tsx` no longer reads `dismissedReason === "auto_duplicate"` or renders an "auto"/"Dismissed automatically — you already dismissed this earlier." treatment; a dismissed suggestion (of any origin) renders through the same single dismissed-suggestion treatment.
5. `dismissSuggestion` (`dismissedReason: "user"`), `reopenSuggestion`, and `closeOpenSuggestions` (`dismissedReason: "round_closed"`) behavior is unchanged — same status transitions and same fields set/cleared as before this story.
6. A `Review` JSON file on disk from before this change, containing a suggestion with `dismissedReason: "auto_duplicate"` and a `duplicateOf` value, still loads (via `ReviewStore.load`) without throwing.
7. Every call site of `addSuggestions` (`packages/server/src/session.ts`'s `runReviewPass`) compiles and runs without passing a `dedupe` option or reading a `duplicates` result field, and the severity cap (`applyCap`) behavior — kept/dropped counts, highest-severity-first-then-file-then-line ordering — is unaffected by this change.

## Dev Notes

<!-- LOCKED. External dev tools must not edit Dev Notes. -->

- **Requirement:** FR-010 — "An automatic suggestion pass no longer suppresses a finding because it resembles a suggestion dismissed in an earlier round," with the four acceptance criteria this story's ACs are drawn from directly: `addSuggestions` keeps only the severity cap; `dismissedReason: "auto_duplicate"`, `duplicateOf`, `findDuplicate`, `similarity`/`normalize`/`words`/`rangesOverlap`, `DedupeConfig`/`DEFAULT_DEDUPE`, and the config `dedupe` field are removed, including any reference in `SuggestionCard.tsx`; `"user"`/`"round_closed"` dismissal behavior is unchanged; and a review persisted before this change with `dismissedReason: "auto_duplicate"`/`duplicateOf` still loads without error since those are just historical values on an existing union member being narrowed going forward, not a shape the loader needs to migrate away. [Source: tech-spec.md#fr-010-remove-suggestion-remembering-cross-round-duplicate-suppression-must]
- **Architecture/Key Components:** the "Suggestion dedupe removal (Round 2)" component entry scopes the removal to `packages/core/src/review/suggestions.ts` (remove `findDuplicate`/`similarity`/`normalize`/`words`/`rangesOverlap`/`DedupeConfig`/`DEFAULT_DEDUPE` and the `duplicates`/`dropped`-via-dedupe branch of `addSuggestions`, keeping only `applyCap`), `packages/core/src/config.ts` (remove `dedupe` from `ReviewGateConfig`/`DEFAULT_CONFIG`/`mergeConfig`), and `packages/web/src/components/SuggestionCard.tsx` (simplify the `auto`/`dismissedReason === "auto_duplicate"` handling). Interface change: `addSuggestions(review, incoming, { cap })` — `dedupe` removed from the options signature; `AddSuggestionsResult` drops `duplicates`. [Source: tech-spec.md#suggestion-dedupe-removal-round-2--packagescoresrcreviewsuggestionsts]
- **Epic scope confirmation:** Epic 7's architecture touchpoints list exactly these three files, and its "Out of scope" note is explicit — "Any change to `applyCap`, severity ordering, or the accept/dismiss/reopen lifecycle — only the dedupe step is removed." Epic 7 has zero cross-epic dependencies and touches no file any other Round 2 epic touches. [Source: bmad-output/epics.md#epic-7-suggestion-dedupe-removal]
- **Backward-compatibility note (Other NFR):** "removing the `dedupe` field from `ReviewGateConfig` (FR-010) is a config shape change; an existing `.reviewgate.json` with a `dedupe` key must simply have that key ignored on load (`mergeConfig` already ignores unknown keys by construction — confirm this stays true rather than erroring)." Reading `mergeConfig` directly (`packages/core/src/config.ts`) confirms it builds a fresh object field-by-field from `DEFAULT_CONFIG` plus recognized keys off `c: Record<string, unknown>`, so an unrecognized `dedupe` key on the input is inert by construction — no error-handling change needed there. [Source: tech-spec.md#other]
- **Why old persisted `auto_duplicate` data is safe without a migration** [Inference, grounded in reading `packages/core/src/review/store.ts` directly]: `ReviewStore.load` does `migrateLegacyChat(JSON.parse(raw))`, and `migrateLegacyChat` casts the parsed blob with `raw as Review & { chat?: ChatMessage[] }` — there is no runtime schema/enum validation of `dismissedReason` anywhere in the load path. TypeScript union types are erased at compile time, so narrowing `DismissedReason` to `"user" | "round_closed"` cannot by itself cause a load-time throw for an old file's `"auto_duplicate"` value; the risk to actually avoid is introducing a *new* runtime check (e.g. an exhaustive `switch` over `DismissedReason` with a `default: throw`) anywhere in this story's changes — do not add one.
- **Exact current code being removed/changed**, read directly from `packages/core/src/review/suggestions.ts`:
  - `addSuggestions` currently does `findDuplicate` per incoming item first, splitting into `duplicates`/`fresh`, then `applyCap(fresh, options.cap)`; after this story it should just be `applyCap(incoming, options.cap)` with the resulting `kept` mapped to `pending` suggestions and `dropped` returned as today. [Source: packages/core/src/review/suggestions.ts]
  - `reopenSuggestion` currently does `const { dismissedReason: _reason, duplicateOf: _dup, ...rest } = s;` — once `duplicateOf` is removed from `Suggestion`, this must become `const { dismissedReason: _reason, ...rest } = s;` or it will fail to compile. [Source: packages/core/src/review/suggestions.ts]
  - `build()`'s `state` parameter is typed `Pick<Suggestion, "status"> & Partial<Pick<Suggestion, "dismissedReason" | "duplicateOf">>` — narrow to drop `"duplicateOf"` once the dedupe branch (the only caller that ever passed it) is gone. [Source: packages/core/src/review/suggestions.ts]
- **`packages/server/src/session.ts` call site**, read directly: `runReviewPass` calls `addSuggestions(this.#review, findings, { cap, dedupe: this.config.dedupe })`, then `await this.#logDedupe(result.duplicates)`. `#logDedupe` is a private method that writes every automatic dismissal to `<gitDir>/reviewgate/dedupe.log` for later threshold tuning (§15) — it has no purpose once dedupe is removed and should be deleted along with its call. Its only reason for importing `fs`/`path`/`Suggestion` in this file appears to be this method — verify (via grep) that `fs.`/`path.`/the `Suggestion` type are not used anywhere else in `session.ts` before removing those imports, since accidentally leaving an unused import behind is a stricter-lint failure while removing a still-used one is a compile failure. [Source: packages/server/src/session.ts]
- **`SuggestionCard.tsx` UI change:** the component currently derives `const auto = suggestion.dismissedReason === "auto_duplicate";` and renders a `{auto && <p>...Dismissed automatically...</p>}` block right after the suggestion body. Removing the derived value and the conditional block is sufficient to satisfy "removed or simplified accordingly" — no replacement copy is required by FR-010; a suggestion that happens to still carry a historical `"auto_duplicate"` value from an old file simply renders identically to any other dismissed suggestion (still governed by the existing `dismissed = suggestion.status === "dismissed"` styling). [Source: packages/web/src/components/SuggestionCard.tsx]
- **Untouched by design:** `packages/server/src/agent.ts`'s `reviewPass` builds a "Findings dismissed earlier — do not repeat these" prompt section from suggestions where `dismissedReason === "user"` — this is a soft, prompt-level hint to the model, not the deterministic `findDuplicate` mechanism this story removes, and `"user"` remains a valid `DismissedReason` after this change, so this code needs no edit. [Inference, grounded in reading packages/server/src/agent.ts directly]
- **Out of scope reminder:** `applyCap`, severity ordering (`SEVERITY_ORDER`), and the accept/dismiss/reopen lifecycle's externally-visible behavior (routes in `app.ts`, `reviewClient.ts`) must not change — this story only removes the dedupe step and its supporting types/config/UI. [Source: bmad-output/epics.md#epic-7-suggestion-dedupe-removal]

- **Key scenarios:**
  - `addSuggestions` given an incoming finding highly similar to an earlier user-dismissed suggestion now adds it as `pending` instead of auto-dismissing it (replaces/repurposes the old "auto-dismisses a repeated suggestion" test into a "does NOT auto-dismiss" assertion) — proves AC #1.
  - `addSuggestions`'s cap behavior (kept/dropped counts, ordering by severity-then-file-then-line) is unchanged from the existing `applyCap`-focused tests still present in `suggestions.test.ts` after the dedupe-only tests are deleted — proves AC #7.
  - `mergeConfig({ dedupe: { ... } })` returns a config object with no `dedupe` property and does not error — proves AC #3.
  - `dismissSuggestion`, `reopenSuggestion`, `closeOpenSuggestions` existing tests in the `describe("status changes", ...)` block continue to pass after `reopenSuggestion`'s `duplicateOf` destructure is simplified (the `reopenSuggestion` test itself needs its `duplicateOf`-asserting line removed since the field no longer exists on the type going forward, but the status/`dismissedReason` assertions must still hold) — proves AC #5.
  - A regression test that either hand-constructs a plain object (bypassing the `Suggestion` type, e.g. via `JSON.parse`/`as unknown as Review`) with `dismissedReason: "auto_duplicate"`/`duplicateOf: "x"` and feeds it through `ReviewStore.load`/`migrateLegacyChat`, or writes such JSON to a temp `ReviewStore` fixture (mirroring `store.test.ts`'s existing temp-repo pattern) and reads it back — asserting no throw and that the suggestion round-trips — proves AC #6.

- **Edge cases to cover:** an incoming finding that is a near-exact duplicate of a `"round_closed"`-dismissed suggestion (never suppressed even before this change, per FR-010's existing "only what you dismissed" rule — should remain unaffected/unsuppressed after this change too, since the whole mechanism is gone); a `.reviewgate.json` with a `dedupe` key alongside other valid keys (confirms only `dedupe` is dropped, not sibling keys); an old-shape review whose `dismissedReason: "auto_duplicate"` suggestion is later reopened via `reopenSuggestion` — should transition to `pending` and drop `dismissedReason` cleanly even though the object arrived with an extra, no-longer-typed `duplicateOf` property still physically present on it from disk.
